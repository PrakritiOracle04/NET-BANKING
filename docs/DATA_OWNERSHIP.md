# Banking Data Ownership

This document defines the source of truth for customer onboarding data. A field may appear in an API response assembled from multiple services, but it should be persisted only by its owning service unless an immutable audit snapshot is required.

| Data | Owning service | Persisted in |
|---|---|---|
| Username, password hash, email, phone, role and login status | Auth | `APP_USER` |
| Legal name, parent/spouse name, date of birth and postal address | Customer | `CUSTOMER_PROFILE` |
| Aadhaar, PAN and KYC verification state | Customer | `CUSTOMER_KYC` |
| Branch directory and IFSC details | Branch | `BRANCH` |
| Account number, type, branch IFSC, balances and account status | Account | `ACCOUNTS` |
| Beneficiary name, relationship, account number and IFSC | Beneficiary | `BENEFICIARIES` |
| Financial transaction history | Transaction | `BANK_TRANSACTIONS` |
| Saga state and compensation metadata | Banking Workflow | `BANKING_WORKFLOWS` |
| Email delivery state and recipient snapshot | Notification | `EMAIL_NOTIFICATION`, `EMAIL_DELIVERY_LOG` |

## Rules

- The authenticated JWT subject supplies `userId`; public request bodies must not select their owner.
- Registration accepts email and phone once. Customer and Account tables do not copy them.
- Account IDs and account numbers are generated by Account service.
- Account opening reuses the existing customer profile and verified KYC record.
- Aadhaar and PAN are encrypted at rest. APIs expose masked identifiers only.
- Cross-service identifiers are logical references. Physical foreign keys are limited to tables owned by the same service.

## Intentional snapshots

Some repeated values are retained deliberately:

- `BANK_TRANSACTIONS.ACCOUNT_NUMBER` preserves the account number displayed when the transaction occurred.
- Workflow account, transaction and reference fields are required for idempotency and compensation recovery.
- `EMAIL_NOTIFICATION.RECIPIENT` records the actual delivery destination used for that notification.
- `CUSTOMER_USER_ID` in domain tables supports ownership checks without joining another service's database tables.

These snapshots must not become an alternative source of truth for mutable customer profile data.
